# 🤖 Интеллектуальный чат-бот с базой знаний (RAG-система)

[![Python](https://img.shields.io/badge/Python-3.10+-blue.svg)](https://www.python.org/)

**Retrieval-Augmented Generation (RAG)** — система, которая отвечает на вопросы на основе ваших документов. Загрузите файлы в базу знаний — бот найдёт релевантные фрагменты и сформирует точный ответ с указанием источников.

> 💡 **Ключевая особенность:** загрузите документы (PDF, DOCX, TXT, CSV, XLSX) — система автоматически извлечёт из них информацию, построит эмбеддинги и будет отвечать на вопросы по содержимому, ссылаясь на конкретные файлы.

## 🎯 Что это?

- 📚 **База знаний** из документов: `PDF`, `DOCX`, `TXT`, `CSV`, `XLSX` + **OCR** для сканированных PDF
- 🔍 **Гибридный поиск**: семантический (эмбеддинги) + лексический (BM25)
- 💬 **Генерация ответов** через LLM (DeepSeek / OpenRouter / DashScope) с источниками-ссылками
- 💲 **Справочник цен**: прайс-листы (XLSX/CSV) разбираются в базу данных, цены выдаются точно, без вызова LLM
- 👥 **Изоляция данных**: у каждого пользователя своя база знаний
- 🖥️ **Интерфейсы**: веб-интерфейс, CLI-лаунчер, Telegram-бот
- 🏠 **Публичный лендинг** — система продаётся как готовый продукт «AI-Ассистент»

## ✨ Возможности

### 📚 База знаний

| Формат | Как обрабатывается |
|--------|--------------------|
| `.txt` | Строки → отдельные фрагменты (факты) |
| `.csv` | Универсальный парсер: `Колонка — значение, Колонка2 — значение2.` (автоопределение разделителя `;`/`,`, кодировок utf-8/cp1251) |
| `.xlsx` | Все листы, первая строка — заголовки колонок |
| `.pdf` | PyMuPDF (fitz), при сканах — **OCR** (DashScope qwen-vl-ocr) |
| `.docx` | Абзацы и таблицы |

- **Загрузка через веб-интерфейс**: drag&drop или выбор файлов, мультизагрузка
- **Фоновая переиндексация**: ответ не блокируется на время обработки больших файлов
- **TXT-приоритет**: если рядом с файлом лежит одноимённый `.txt`, эмбеддинги строятся по нему, оригинал остаётся на диске для скачивания
- **Кэш эмбеддингов** по хэшу содержимого — повторная обработка без пересчёта
- **Группы документов** (автоопределение по имени и содержимому): Каталоги, Инструкции, Паспорта, Прайс-листы и т.д.
- **Индексация сайта по ссылке**: обход сайта по адресу → один TXT-файл в базе знаний (кнопка «🌐 Индексировать сайт»)
- **Сортировка** и **bulk-операции**: удаление и скачивание нескольких документов (ZIP-архивом)

### 🔍 Поиск и ответы

- **Гибридный поиск**: семантический (sentence-transformers, multilingual-e5-large) + BM25, с настраиваемым весом
- **Ответы с источниками**: в конце ответа список файлов — кликабельные ссылки на скачивание
- **Прайс-листы**: вопрос «сколько стоит…» перехватывается и отвечается **из таблицы цен PostgreSQL без LLM** — ноль галлюцинаций
- **Персональный промт**: у каждого пользователя свой системный промт (задаёт характер бота), приветствие в чате формируется из роли промта
- **История диалогов** в PostgreSQL, удаление отдельных пар «вопрос-ответ»

### 🖥️ Интерфейсы

- **Веб-интерфейс** (Flask, порт **8077**): публичный лендинг (`/`), регистрация/вход, чат (`/chat`), панель документов
- **CLI-лаунчер** (`run_cli.py`): меню в терминале (навигация стрелками) — запуск веб-сервера и Caddy, настройки (LLM, поиск, OCR, Telegram, пути Caddy), пользователи и промты, Telegram-бот
- **Telegram-бот**: команды `/start`, `/help`, `/stats`, отвечает на вопросы и принимает документы прямо в чат

### ⚙️ Дополнительно

- **OCR** сканированных PDF (qwen-vl-ocr через DashScope, ~$0.00017/страница, с кэшем)
- **Логирование чатов** в `chat_logs/`
- **Настройки без рестарта**: изменения в лаунчере применяются к следующему запросу (горячая перезагрузка из БД, таблица `app_settings`)
- **Rate-limit** на `/ask` (30 запросов/мин на пользователя), **CSRF-защита**

## 🏗️ Как это работает

```
Пользователь задаёт вопрос
        │
        ▼
┌─────────────────────────────────────────┐
│  Гибридный поиск в базе знаний          │
│  (семантический + лексический BM25)     │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Найдены релевантные фрагменты          │
│  из загруженных документов              │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Генерация ответа через LLM             │
│  (DeepSeek / OpenRouter / DashScope)    │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Ответ пользователю + источники         │
└─────────────────────────────────────────┘
```

**Хранение данных — гибридное:**

- **PostgreSQL** — метаданные: пользователи, документы, история чатов, прайс-позиции, персональные промты
- **Файловая система** — сами документы: `Database/` (общая база) и `Database/user_{id}/` (личная база каждого пользователя)
- **Кэш эмбеддингов** — `embeddings_cache/user_{id}/` (пересоздаётся автоматически)

## 🚀 Установка

### Предварительные требования

- Python **3.10+**
- **PostgreSQL** (локально или на сервере) — база данных `rag_system`
- ~4 ГБ ОЗУ (модель эмбеддингов multilingual-e5-large ≈ 2 ГБ)
- API-ключ LLM-провайдера (DeepSeek / OpenRouter / DashScope)

### Шаг 1: Клонирование

```bash
git clone https://github.com/petrlev1/assistant.git
cd assistant
```

### Шаг 2: Виртуальное окружение

**Windows:**

```bash
python -m venv venv
venv\Scripts\activate
```

**Linux/macOS:**

```bash
python3 -m venv venv
source venv/bin/activate
```

### Шаг 3: Зависимости

```bash
pip install -r requirements.txt
```

### Шаг 4: PostgreSQL

Создайте базу данных (таблицы создадутся автоматически при первом запуске веб-сервера):

```sql
CREATE DATABASE rag_system;
```

Параметры подключения указываются в `db_config.json` (`db_host`, `db_port`, `db_name`, `db_user`, `db_password`) или переменными окружения `PGHOST` / `PGPORT` / `PGDATABASE` / `PGUSER` / `PGPASSWORD` (env имеет приоритет). Файл создаётся автоматически при первом запуске: если `db_config.json` отсутствует, а в БД ещё нет таблицы `app_settings` — параметры переносятся из устаревшего `rag_settings.json` (одноразовая миграция).

### Шаг 5: Настройка

Запустите **CLI-лаунчер** (`venv\Scripts\python.exe run_cli.py`) и задайте настройки в меню — настройки (провайдер LLM, ключи API, параметры поиска, OCR, Telegram) сохраняются в PostgreSQL (таблица `app_settings`). Файла конфигурации настроек больше нет.

## ⚙️ Настройка

Все настройки хранятся в PostgreSQL — таблица `app_settings` (ключи API, провайдер, параметры поиска/OCR, токен Telegram, пути Caddy). Управляются через лаунчер (меню `run_cli.py` или команда `run_cli.py settings set <ключ> <значение>`); вносить изменения напрямую в БД не требуется.

### LLM-провайдер

| Параметр | Назначение |
|----------|-----------|
| `llm_provider` | Провайдер: `DeepSeek` / `OpenRouter` / `DashScope` / `Local (llama.cpp)` |
| `llm_base_url` | Базовый URL API (например `https://api.deepseek.com/v1`) |
| `llm_model` | Модель (например `deepseek-v4-flash`) |
| `llm_provider_api_key` | Ключ DeepSeek |
| `llm_openrouter_api_key` | Ключ OpenRouter (`sk-or-...`) |
| `llm_api_key` | Ключ DashScope — **общий с OCR, не перезаписывайте** |

> Ключ выбирается по активному провайдеру, а не по приоритету fallback — переключение провайдера в лаунчере не ломает OCR.

### Параметры поиска

| Параметр | По умолчанию | Назначение |
|----------|--------------|-----------|
| `search_top_k` | 10 | Сколько фрагментов искать (правится в админке: блок «Модели» → «Поиск по векторам») |
| `search_alpha` | 0.7 | Вес семантического поиска (0–1) |
| `relevance_threshold` | 0.2 | Минимальная релевантность фрагмента |
| `max_context_fragments` | 100 | Максимум фрагментов в контексте |

### Флаги управления

| Флаг | Эффект |
|------|--------|
| `disable_llm_models` | Пропустить вызов LLM, вернуть найденный контекст как есть (режим «смотреть сырые данные») |
| `disable_hybrid_search` | Отключить гибридный поиск |
| `disable_knowledge_base_search` | Работать только через LLM, без поиска в базе |

### OCR (сканированные PDF)

| Параметр | По умолчанию | Назначение |
|----------|--------------|-----------|
| `ocr_enabled` | false | Включить OCR для страниц без текстового слоя |
| `ocr_model` | `qwen-vl-ocr` | Модель OCR (DashScope) |
| `ocr_base_url` | dashscope-intl | URL API |
| `ocr_dpi` | 150 | Разрешение рендера страницы |

OCR вызывается **только** для страниц, где текстовый слой пуст — обычные PDF не тратят ни копейки. Результаты кэшируются (`embeddings_cache/<user>/ocr_cache/<хэш файла>/<модель>/`). Кэш разбит **по модели OCR**: после смены `ocr_model` страницы распознаются заново (старый кэш остаётся на диске), поэтому смена модели = новый расход квоты DashScope.

### Смена моделей из админ-панели (`/admin`)

Скрытая страница `/admin` (вход по отдельной учётке из `admin_config.json`) содержит блок **«Модели»** — то же, что настройки в CLI-лаунчере, но из браузера:

- **LLM**: провайдер (DashScope / DeepSeek / OpenRouter / Local (llama.cpp)), модель (список из каталога или своя), base_url, флаг «Отключить отправку запросов к LLM»;
- **OCR**: вкл/выкл, модель (`qwen-vl-ocr` / `qwen-vl-plus` / `qwen-vl-max` или своя), base_url, DPI;
- **API-ключи**: DashScope (он же ключ OCR), DeepSeek, OpenRouter — **пустое поле = ключ не меняется**, значения на страницу не отдаются (только признак «задан / не задан»);
- **Поиск по векторам**: `search_top_k` — сколько фрагментов базы знаний уходит модели; значение одно для всех моделей (больше контекста = длиннее промпт и позже первый ответ, особенно у локальной модели на GPU). Модель эмбеддингов показывается справочно — она прошита в коде (`rag_core._get_embedding_model()`), из админки не переключается (смена требует полной переиндексации всех баз знаний).

Настройки общие для всех пользователей (таблица `app_settings`) и применяются **со следующего запроса, без перезапуска сервера** (`ask_model()` делает `settings.reload()`, а сохранение из админки перечитывает настройки сразу). Списки провайдеров и моделей — общий файл `model_catalog.py` (им пользуются и CLI, и админка).

### Локальная модель вместо облака (`Local (llama.cpp)`)

Ответы можно считать на своей GPU: рядом с приложением поднимается OpenAI-совместимый сервер
(`llama-server`, по умолчанию `http://127.0.0.1:8080/v1`), в админке выбирается провайдер
**Local (llama.cpp)**, а модель указывается та, что задана у сервера в `--alias`. Ключ не нужен:
провайдер помечен `local`, и облачный `llm_api_key` к нему не подставляется (пустая строка уронила бы
клиент `openai` с «Missing credentials»). `search_top_k` для локальной модели держите ниже, чем для
облачной (10–15): время до первого слова растёт вместе с длиной промпта. OCR остаётся облачным —
у него отдельные `ocr_base_url` и ключ DashScope.

### Прочее

- `telegram_bot_token` — токен Telegram-бота (от @BotFather)
- `caddy_path`, `caddy_dir` — путь к Caddy (для внешнего домена)
- `SECRET_KEY` (env) или файл `.secret_key` — ключ подписи сессий (создаётся автоматически; без него пользователей разлогинивает при каждом рестарте)

## ▶️ Запуск

### Способ 1: CLI-лаунчер (рекомендуется)

```bash
venv\Scripts\python.exe run_cli.py
```

Откроется интерактивное меню (стрелки ↑/↓, Enter — выбор, Esc — отмена):

1. **«Веб-интерфейс»** → **«Запустить»** — выберите режим:
   - **Локальный** — `http://localhost:8077`, Caddy не нужен
   - **Внешний адрес** — `http://<ваш-ip>:8077` (нужен проброс порта)
   - **Внешний домен** — Caddy (TLS) → `ваш домен` → `localhost:8077` (если Caddy уже запущен системно — CLI использует существующий, дубль не поднимает)
2. После запуска откройте `http://localhost:8077` в браузере.

Разделы меню: **Настройки** (провайдер/ключи/модель, поиск, OCR, Telegram, пути Caddy — значения выбираются стрелками, ввод с предзаполнением текущего), **База знаний** (информация, перезагрузка RAG), **Telegram-бот**, **Пользователи** (список, персональные промты), **Остановить всё**.

Те же операции доступны одной командой без меню: `run_cli.py status`, `run_cli.py web start --mode local`, `run_cli.py settings set llm_provider DeepSeek`, `run_cli.py users prompt get <user>` — полный список в `run_cli.py --help`.

## 📚 База знаний

### Загрузка документов

**Вариант 1 — через веб-интерфейс** (рекомендуется): «📄 Документы» → перетащите файлы в область загрузки или нажмите на неё. Для прайс-листов отметьте «📋 Это прайс-лист» (обычно определяется автоматически).

**Вариант 2 — файловой системой:** скопируйте файлы в папку `Database/` (общая база) или `Database/user_{id}/` (личная база пользователя с id из таблицы `users`). Система подхватит их при следующем обращении к базе знаний.

### Правила для файлов TXT

- **Одна строка = один факт** (50–300 символов) — каждая строка становится отдельным фрагментом для поиска
- Ключевые термины — в начале строки
- Единая терминология во всех файлах
- Разделяйте темы заголовками-комментариями `# Название раздела` — строки, начинающиеся с `#`, в индекс не попадают (это разметка файла для человека)
- **TXT-приоритет:** одноимённый `.txt` рядом с PDF/DOCX перекрывает оригинал для эмбеддингов (оригинал остаётся для скачивания) — удобно, когда нужна доработанная версия

### Индексация сайта по ссылке

В панели «📄 Документы» — кнопка **«🌐 Индексировать сайт»**. Указываете адрес (можно без `https://`),
при необходимости меняете лимит страниц (по умолчанию 50, максимум 300) и запускаете обход. Ответ
приходит сразу, обход идёт в фоне: в панели видна строка прогресса («страниц 12 из 50 · строк 940»)
с кнопкой «Отменить».

- **Результат** — один текстовый файл `site_<домен>.txt` в «Документах» (группа «🌐 <домен>»): каждая
  строка файла — отдельный факт 40–250 символов, разделители страниц начинаются с `#` и в индекс не идут.
  Эмбеддинги и BM25 создаются штатным конвейером, отдельный «файл эмбеддингов» не нужен.
- **Повторный запуск по тому же адресу = обновление**: страницы запрашиваются с `If-None-Match` /
  `If-Modified-Since`, неизменившиеся (ответ 304) берутся из кэша, исчезнувшие уходят из файла, а
  страницы, до которых обход не добрался (лимит, отмена, сбой сети), сохраняются с прежним текстом.
  Файл заменяется целиком — дубликатов документов не появляется; если текст не изменился, эмбеддинги
  не пересчитываются. Обновить можно кнопкой **⟳** у файла сайта в списке документов.
- **Что попадает в файл**: основной текст страниц без меню, подвала, куки-баннеров и `<script>`; ссылки
  обходятся только внутри того же сайта (поддомены не трогаются), robots.txt уважается (галочка в диалоге).
- **Ограничения**: только статические страницы — сайты, рисующие контент на JavaScript (SPA), отдадут мало
  текста; PDF-файлы сайта не разбираются; максимум 10 000 строк и 50/300 страниц за один обход.
- **Безопасность**: разрешены только `http://` и `https://`, адреса внутренней сети (localhost, 10/8,
  192.168/16, 169.254.169.254 и т.п.) отклоняются — в том числе на каждом шаге редиректов.
- Кэш обхода (сырой HTML + собранный текст страниц) лежит в `site_cache/user_{id}/<домен>/` и в git не попадает.

### Прайс-листы

- Поддерживаются `.xlsx` (все листы) и `.csv` (разделители `;`/`,`, кодировки utf-8/cp1251)
- Шапка определяется автоматически по колонкам «цена»/«наименование»/«артикул»
- Позиции попадают в таблицу `price_items` (PostgreSQL): точный поиск по артикулу и названию, ответ без LLM
- Повторная загрузка файла с тем же именем **заменяет** документ и прайс — дубликатов не будет
- Не поддерживается старый бинарный `.xls` (файл будет отклонён с понятной ошибкой)

## 🔒 Безопасность

- Пароли пользователей хранятся только как хэши (werkzeug); восстановить исходный пароль невозможно — только сброс
- Изоляция данных: пользователь видит только свои документы и историю
- Защита от path traversal при загрузке файлов (`os.path.basename`)
- CSRF-проверка Origin для изменяющих запросов
- Rate-limit на `/ask` (30 запросов/мин на пользователя)
- Секреты: ключи API и токен Telegram — в БД (таблица `app_settings`), пароль БД — в `db_config.json` (вне git); в коде секретов нет
- Стабильный ключ сессий в `.secret_key` (вне git) — пользователей не разлогинивает при рестарте
